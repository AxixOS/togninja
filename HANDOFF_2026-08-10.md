## 1. Can you just clone and continue?

**Almost.** The code is fully pushed — working tree clean, `promote-1.8.22` matches the
`product` remote's `main`. But the repo alone will not run.

You need **two things that are deliberately not in git**:

1. **`.env`** — `.env` is gitignored (correctly; it holds live credentials). Get it from
   Matt. Minimum to boot: `DATABASE_URL`, `ENCRYPTION_KEY`, `SESSION_SECRET`.
   `ENCRYPTION_KEY` matters more than it looks — every stored credential (SMTP, Stripe,
   OpenAI) is AES-256-GCM encrypted with it. A different key means every saved integration
   silently fails to decrypt.
2. **Push access** to `github.com/AxixOS/togninja` (remote `product`).

```bash
git clone <this repo> && cd workingnewage
npm install --legacy-peer-deps
cp <the .env you were given> .env
npm run dev
```

## 2. What this project is

One product codebase, many single-tenant instances. **One database = one studio.** The
`studio_configs` singleton row is the tenancy anchor — everything reads it with `LIMIT 1`.

It began as one studio's site (**New Age Fotografie**, Vienna) and is being turned into a
product any photographer can buy. The bulk of recent work is removing that origin studio
from the image so a buyer sees only their own business.

**Test tenant:** Susan Grace Hinman, a Brighton (UK) boudoir photographer — deliberately
as unlike a Viennese family studio as possible, which is what keeps surfacing leaks.

## 3. Branches and deploying

```
local main  ──cherry-pick──▶  promote-1.8.22  ──push──▶  product/main  ──▶ GHCR ──▶ Render
```

```bash
git checkout promote-1.8.22
git cherry-pick <sha-from-main>          # use the SHA, not "main" — see §7
git push product promote-1.8.22:main
git tag v1.8.79 <promote-sha> && git push product v1.8.79
```

**Tag the commit on `promote-1.8.22`, not the one on `main`.** They are different SHAs
(cherry-picks). Tagging main's SHA produces a tag that is not on the deployed branch — this
happened twice on 9–10 Aug and had to be undone both times.

**Instance:** `togninja.onrender.com` (DEMO_MODE, Susan's tenant). Admin at `/admin`,
wizard at `/setup`.

## 6. How to verify work

`tsc` being unreliable, the real checks are:

```bash
# 1. Production build (catches JSX/syntax)
npx vite build --mode production

# 2. Boot the PRODUCTION handler — dev uses a DIFFERENT catch-all and cannot
#    show you SSR meta, prerendering, or the sitemap. Three rounds were lost to this.
NODE_ENV=production PORT=5265 PUBLIC_SITE_URL=https://example.com npx tsx server/index.ts

# 3. Render every public page and search what a VISITOR sees
node scripts/check-visible-leaks.mjs http://localhost:5265
```

`check-visible-leaks.mjs` reads visible text **plus** iframe sources, `title`/`alt`/
`aria-label`, the document title and meta description — because a grep over `client/src`
counts defaults no studio renders, and an iframe contributes nothing to `innerText`. It
exits non-zero on a leak **or on a page it could not inspect**. It once reported "23 pages,
0 visible" while every page had failed on a `ReferenceError`; a false all-clear gets
believed, so unchecked pages now fail the run.

## 7. Gotchas that cost real time

- **Never bulk-regex a file.** A tidy rule matched every line's indentation and reformatted
  1,731 lines. A later one broke prose. Work line by line, assert the bounds before
  deleting, and check `git diff --numstat` shows equal added/removed.
- **Route shadowing in `server/routes.ts`** (~20k lines). Duplicate registrations for the
  same path; Express matches first-registered and the later handler never runs. Hit four
  times. Suspect it whenever a handler "cannot possibly be doing that".
- **Dev vs production handlers.** `setupVite()` and `serveStatic()` each register their own
  `app.use("*")`. SSR meta lives only in the production one.
- **Two language values with similar names.** `studio_configs.site_language` drives page
  visibility, generated copy and URLs. `i18n_settings.default_language` drives which
  translation set the public site renders. They were never linked — a studio onboarded in
  English served German. Set one, set the other.
- **Connection pool budget.** Three pools share one Supabase pooler (`server/db.ts`,
  `server/auth.ts`, `database.js`). Their sum must stay under the pooler's limit or
  everything 500s with `EMAXCONNSESSION`. The sum is asserted at boot — read that line.
- **Code defaults do not rewrite published content.** `manual_page_content` holds
  snapshots. Changing a default has no effect on a studio that already published; use the
  page's Reset, or a forced regenerate.
- **Empty string is a deliberate value.** Several keys are `''` on purpose; truthiness
  checks treat them as missing.

## 8. Useful commands

```js
// Wipe to pre-onboarding (DEMO_MODE only; signs you out — you make a new admin in the wizard)
await fetch('/api/setup/reset-demo', { method: 'POST', credentials: 'include' }).then(r => r.json()).then(console.log)

// Re-crawl + regenerate. force=1 OVERWRITES existing copy
await fetch('/api/setup/homepage/generate?force=1', { method: 'POST', credentials: 'include',
  headers: { 'Content-Type': 'application/json' }, body: '{}' }).then(r => r.json()).then(console.log)

// Build + publish pillar pages without a full regenerate
await fetch('/api/authority-map/scaffold', { method: 'POST', credentials: 'include',
  headers: { 'Content-Type': 'application/json' }, body: JSON.stringify({ publish: true }) })
  .then(r => r.json()).then(d => console.log(JSON.stringify(d, null, 2)))
```

Public GETs, readable from anywhere: `/api/version`, `/api/studio-config`,
`/api/authority-map`, `/api/manual-pages/published/all`, `/sitemap.xml`.
